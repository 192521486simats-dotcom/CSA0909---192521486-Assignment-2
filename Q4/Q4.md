1. Inputs and Outputs
Problem context: A hospital pharmacy maintains stock details for medicines. Each medicine is identified by a unique medicine code. Pharmacists frequently search for medicines, while the system generates two reports every evening:
1.	Medicines arranged in medicine-code order.
2.	Medicines arranged in the order they were added.
Input:
•	Medicine code.
•	Medicine name.
•	Available stock quantity.
•	Medicine price.
•	Number of medicines stored.
•	Medicine codes used for lookup.
Output:
•	Medicine details for a requested code.
•	Report sorted by medicine code.
•	Report in insertion order.
•	Execution time for lookup and report generation.
Objective: Compare HashMap, TreeMap and LinkedHashMap and select an appropriate map for the pharmacy inventory system.

2. Prediction and Design Reasoning
A. HashMap
HashMap stores key-value pairs using hashing.
•	Provides O(1) average-time insertion and lookup.
•	Does not guarantee any particular iteration order.
•	Requires sorting the entries when a code-ordered report is needed.
•	Suitable for frequent medicine-code lookups.
B. TreeMap
TreeMap stores keys in sorted order using a Red-Black Tree.
•	Provides O(log n) insertion and lookup.
•	Automatically maintains keys in sorted order.
•	Naturally generates the medicine-code report.
•	Does not preserve insertion order.
C. LinkedHashMap
LinkedHashMap maintains a linked order of entries.
•	Provides O(1) average-time insertion and lookup.
•	Preserves insertion order by default.
•	Naturally generates the report in the order medicines were added.
•	Requires sorting for a medicine-code-ordered report.
Predicted complexity comparison

Operation	HashMap	TreeMap	LinkedHashMap
put()	O(1) average	O(log n)	O(1) average
get()	O(1) average	O(log n)	O(1) average
Iteration	O(n)	O(n)	O(n)
Code-order report	Requires sorting	Direct iteration	Requires sorting
Insertion-order report	Not guaranteed	Not preserved	Direct iteration
Here, n represents the number of medicines stored.

Compare the calculated average with the defined target.
Where does the remaining cost come from?
Even when a map provides fast lookup, other operations still require processing:
•	HashMap must sort its keys to generate a code-order report.
•	LinkedHashMap must sort its keys to generate a code-order report.
•	TreeMap must traverse its entries to generate a report.
•	All maps require O(n) iteration to process every medicine.
Why is Hashtable not preferred in new Java code?
Hashtable is an older synchronized collection.
•	Its methods are synchronized, which can introduce unnecessary synchronization overhead.
•	It does not allow null keys or null values.
•	Modern alternatives provide more flexibility.
•	HashMap is suitable for ordinary non-thread-safe use.
•	ConcurrentHashMap is generally preferred for concurrent access when thread-safe key-value operations are required.

6. Alternative Concept and Complexity Analysis
Instead of using a Map, the pharmacy inventory can be maintained in an array sorted by medicine code. Arrays.binarySearch() can then locate medicines.
Example implementation
import java.util.Arrays;
import java.util.Comparator;

class Medicine {

    String code;
    String name;
    int quantity;

    Medicine(String code, String name, int quantity) {
        this.code = code;
        this.name = name;
        this.quantity = quantity;
    }

    @Override
    public String toString() {
        return code + " - " + name + " - " + quantity;
    }
}

public class SortedArrayDemo {

    public static void main(String[] args) {

        Medicine[] medicines = {
            new Medicine("MED003", "Tablet C", 50),
            new Medicine("MED001", "Tablet A", 100),
            new Medicine("MED002", "Tablet B", 75)
        };

        // Sort medicines by medicine code
        Arrays.sort(
            medicines,
            Comparator.comparing(m -> m.code)
        );

        String searchCode = "MED002";

        // Binary search using medicine code
        int index = Arrays.binarySearch(
            medicines,
            new Medicine(searchCode, "", 0),
            Comparator.comparing(m -> m.code)
        );

        if (index >= 0) {
            System.out.println("Medicine found:");
            System.out.println(medicines[index]);
        } else {
            System.out.println("Medicine not found");
        }

        System.out.println("\nCode-order report:");

        for (Medicine medicine : medicines) {
            System.out.println(medicine);
        }
    }
}
Output:
Medicine found:

Code-order report:

MED002 - Tablet B - 75
MED003 - Tablet C - 50
Complexity comparison
Let n represent the number of medicines.

Operation	HashMap	TreeMap	Sorted array
Lookup	O(1) average	O(log n)	O(log n)
Insertion	O(1) average	O(log n)	O(n)
Code-order report	O(n log n) including sorting	O(n)	O(n)
Iteration	O(n)	O(n)	O(n)
Space	O(n)	O(n)	O(n)
Explanation:
•	HashMap provides fast average lookup but does not maintain sorted order.
•	TreeMap maintains sorted keys automatically, with O(log n) lookup and insertion.
•	A sorted array supports binary search, but inserting a new medicine requires shifting elements to maintain the sorted order.
•	A sorted array is useful when the inventory is read frequently and updated infrequently.

7. Final Design Decision
For the hospital pharmacy inventory system, HashMap is a suitable choice when fast medicine-code lookup is the primary requirement.
However, the system also needs two different reports:
•	TreeMap naturally produces the medicine-code-ordered report.
•	LinkedHashMap naturally produces the insertion-order report.
Final recommendation:

Requirement	Recommended map
Frequent medicine-code lookup	HashMap
Medicine-code-ordered report	TreeMap
Insertion-order report	LinkedHashMap
If the pharmacy requires all three operations frequently, maintaining separate indexes may be appropriate, but it introduces additional memory usage and requires keeping the maps synchronized whenever inventory changes.
The final deployment choice should be based on the measured lookup time, report-generation time and actual frequency of each operation.
